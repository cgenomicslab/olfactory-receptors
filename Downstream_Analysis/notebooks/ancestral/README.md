# Ancestral repertoires

What the reconstructed ancestral olfactory receptors are predicted to bind, and how that
changes down the human tree.

## How to run

```bash
conda activate olfactory-receptors
python scripts/download_zenodo_data.py       # from the repository root, once
python scripts/check_reproducibility.py      # confirms the inputs below are present
jupyter lab                                  # then run 01 -> 06 in order
```

Every notebook opens with:

```python
import sys; sys.path.append("../../scripts")
from ancestral_sets import load_ancestral
anc = load_ancestral()          # mode="density" -- the default, and the right one
```

`load_ancestral` builds the binarised matrix, the node sets and the activation patterns
once, so the notebooks stay short. The full API is tabulated in
[`../../README.md`](../../README.md#ancestral_setspy).

Notebooks `01`–`05` are independent of each other and can be run in any order; `06` is
self-contained too. The numbering is reading order, not a dependency chain — unlike
`reference_tree/`, where `01` writes a file `03` reads.

| Notebook | Question | Runtime |
|---|---|---|
| `01.node_repertoires` | What do the three core nodes bind, and how do their chemistries differ? | ~1 min |
| `02.pattern_contrasts` | Group ligands by which nodes bind them; contrast the class 1 and class 2 sides. | ~1 min |
| `03.functional_decay` | Does depth in the tree predict how many odorants a receptor binds? | ~2 min |
| `04.parent_child_decay` | How fast does a repertoire change along a branch? Gives the functional half-life. | ~5 min (sweeps) |
| `05.ten_node_lineage` | The same questions across ten nodes, following one lineage down the class 2 trunk. | ~2 min |
| `06.code_trajectory` | Every node on one time axis: how the code fills in from `node_1` to the 433 human receptors. | ~10 min |

Figures are written to `Figures/` as SVG and tables to `Tables/` as CSV, both by
`save_fig` / `save_table`. Both directories are regenerated by re-running the notebooks.

## Binarisation

No threshold is chosen here. Ligand calls come from the density fill in
[`../../scripts/calibration.py`](../../scripts/calibration.py) — one isotonic map, fitted
once on the 23,782 measured human pairs, decides how many cells are on; rank decides which.
The cut is an output.

The ASR and reference matrices are filled separately, each from its own scores:

```
ASR     432 nodes   cut 0.8875   density 2.26%
extant  433 human   cut 0.8947   density 2.75%
```

Neither fill takes an experimental overlay, so ancestors and tips are compared prediction
against prediction. See [`../../README.md`](../../README.md#binarisation-how-a-probability-becomes-a-binding-call)
for why.

The three core nodes hold **21, 21 and 8** ligands. Sizes are relative, not absolute
binding counts — read them node against node. `04` sweeps absolute cuts from 0.3 to 0.915
with the density fill alongside, and the threshold-free weighted Jaccard tracks the same
decay.

### Changing the binarisation

Every function takes a `threshold` argument, and `load_ancestral` takes a `mode`. Both
default to the density fill; pass a number to restore an absolute cut, which is what the
sweeps in `04` do.

```python
anc = load_ancestral()                        # density fill (default)
anc = load_ancestral(mode="absolute", threshold=0.5)   # the old permissive cut
anc = load_ancestral(mode="rank", top_fraction=0.047)  # equal repertoire sizes
edge_table(threshold=None)                    # density fill
edge_table(threshold=0.8)                     # absolute cut, for the sweep
```

Under `mode="absolute"` at 0.5, precision on measured extant pairs is 0.27 — roughly three
in four positives are false. Repertoire sizes under it are not binding counts.

## The node naming

| ASR matrix row | name used in the notebooks | what it is |
|---|---|---|
| `node_1_ASR` | `common_ancestor` | the gnathostome OR ancestor |
| `node_2_ASR` | `class1_ancestor` | ancestor of the 62 Class I receptors |
| `node_3_ASR` | `class2_ancestor` | ancestor of the 371 Class II receptors |

Activation patterns are three-bit strings read in row order **`[class1, common, class2]`**,
so `110` means "bound by the class 1 ancestor and the common ancestor, not by class 2".
`PATTERN_LABELS` in `ancestral_sets.py` names all seven.

Grouped into `code_sets`:

| set | patterns | meaning |
|---|---|---|
| `class1_side` | `100` + `110` | bound by the class 1 ancestor but not class 2 |
| `class2_side` | `011` + `001` | bound by class 2 but not class 1 |
| `shared` | `111` | bound by all three |
| `common_only` | `010` | held by the common ancestor, dropped by both |

## Odour descriptors

Enrichment tests have been removed. The three repertoires span 39 ligands between them, too
few for a hypergeometric, and the split these nodes mark looks chemical rather than
perceptual. `02`'s descriptor and functional-group contrasts ask that question instead.

## Note on the ten nodes

`05` uses nodes 1, 2, 3, 4, 5, 6, 12, 21, 32 and 44 (`TEN_NODES` in `ancestral_sets.py`).
They are not an arbitrary selection: 1 is the common ancestor, 2 and 3 the two class
ancestors, 4 and 5 sit under class 1, and 6 → 12 → 21 → 32 → 44 is a nested chain down the
class 2 trunk. That chain is why the notebook exists — it lets the repertoire be followed
step by step along a single lineage instead of compared across a fork.

## Note on the trajectory notebook

`06` differs from `01`–`05` in that it uses no named node set. It ultrametricises the tree
by mean path length on the ingroup at `node_1`, and reads the repertoire at relative time
*t* as the set of lineages crossing *t*. `mpl_times`, `raw_times`, `lineage_slice`,
`class_clades` and `trajectory` in `../../scripts/ancestral_sets.py` carry that machinery.

Two time axes are computed and should be read together: `mpl_times` assumes rate variation
averages out, `raw_times` assumes no clock at all. The truth is between them, so the pair
brackets the timing rather than pinning it.

It reproduces and checks a collaborator's recipe (A. Pittis, `FOR_IORDANA_trajectory.md`).
Two of its three acceptance tests pass; the third — the extant endpoint at 17 / 370 / 300 —
requires the experimental overlay on extant rows, which this folder deliberately does not
use, because overlaying measurements on tips alone puts a data-source discontinuity on
every ancestor-to-tip edge. The no-overlay endpoint is **15 / 342 / 311**, and
`Tables/06_endpoint_overlay.csv` gives both.

**Two results in `06` are negative and worth knowing before reusing its figures:**

- the class-overlap curves sit inside a composition null's 95% band at ~100% of time
  points, so they carry no evidence beyond the changing Class I : Class II ratio
- 29 hyper-broad rows (>100 ligands) carry 45% of the odorants; blanking them moves the
  endpoint from 668 to 371 (`trajectory(..., blank_above=100)`)
